# SchedX-Agent 最终展示视频录制台本

目标视频时长：4 分 40 秒～5 分钟。
录屏工具：FinalShell 录屏、OBS 或其他桌面录制工具。  
演示环境：openEuler 24.03 LTS SP4，`/root/SchedX-Agent`。

时间安排：环境 35 秒，负载识别 25 秒，方案决策 30 秒，自动实验约 2 分钟，结果说明 70 秒，清理总结 20 秒。第 4 幕程序运行时同步讲解，不要等待程序结束后再补讲。

## 录制前准备

1. 将终端字体调到 18～20，窗口最大化，分辨率建议 1920×1080。
2. 不要展示 `/etc/schedx/llm.env`、API Key、SSH 私钥和密码。
3. 在开始录屏前执行：

```bash
cd /root/SchedX-Agent
source .venv/bin/activate
git pull --ff-only gitlink master
bash scripts/demo_cleanup.sh
clear
```

4. 开始录屏后执行：

```bash
cd /root/SchedX-Agent
source .venv/bin/activate
bash scripts/demo_recording_story.sh
```

脚本会在每一幕结束后等待按 Enter。讲解完当前画面，再按 Enter 继续。

## 第 1 幕：项目定位、内核适配与真实环境（约 35 秒）

画面会展示 openEuler、当前内核、资源控制功能、自定义调度功能和大模型状态。

旁白：

> 本项目是 SchedX-Agent，用于保护受后台计算任务干扰的在线服务。演示环境是比赛要求的 openEuler 24.03 LTS SP4。
>
> 原版 SP4 内核没有开启可扩展调度功能，因此我们完成了内核适配。屏幕中的 schedx1 表示当前使用适配后的真实内核，后续会真实加载调度策略；如果机器不支持这项能力，Agent 也能自动退回资源控制模式。

画面出现环境信息时，依次指出：

- 操作系统是 openEuler 24.03 LTS SP4
- 内核版本末尾包含 `schedx1`
- “可扩展调度功能”显示可用
- Agent 运行模式为真实自定义调度模式，而不是模拟模式

看到 `READY` 后按 Enter。

## 第 2 幕：识别在线服务与后台干扰（约 25 秒）

脚本会启动 nginx 与 stress-ng 混合负载，并输出分类结果。

旁白：

> Agent 识别出五个 nginx 在线服务进程和 stress-ng 后台干扰，因此将当前场景判断为混合负载。识别过程会结合进程信息、资源使用和父子关系，并通过安全名单排除 Agent 自身、远程登录和系统管理进程，避免误操作。

[指向“混合负载”“nginx x5”和“stress-ng”三行，停留两秒，然后按 Enter。]

## 第 3 幕：大模型提出方案，安全规则负责把关（约 30 秒）

脚本会调用 `llm-plan`，显示策略来源、模式、目标、置信度和结构化参数。

旁白：

> DeepSeek 根据混合负载提出优先保护 nginx 的方案，并给出前后台任务优先级。但大模型只有建议权，所有参数还要经过固定格式、目标白名单和安全范围检查，检查通过后才能真实执行；大模型不可用时，系统会自动使用本地规则。

[指向“方案来源”“保护对象”“可信度”和两行优先级，然后按 Enter。]

## 第 4 幕：自动执行并检查效果（约 2 分钟）

脚本调用当前主程序：

```bash
python3 scripts/run_competition_demo.py \
  --output results/video-recording \
  --report reports/video-recording.md \
  --llm-policy \
  --compact \
  --duration 3 \
  --repeats 1 \
  --connections 8 \
  --threads 2 \
  --batch-threads 2 \
  --stress-cpu 2
```

等待期间旁白：

> Agent 正在依次对比默认方案、资源限制、自定义调度和联合优化，然后换用批处理任务验证通用性，最后分别演示方案接受与自动恢复。
>
> 这些都是真实执行：系统先调整资源参数并加载调度策略，再测量响应时间、处理能力和后台任务进度，最后决定接受还是恢复。画面中的“自动恢复”表示方案已经执行，但没有通过全部安全条件。本次短时测试用于展示完整流程，正式性能结论来自多轮实验。

脚本完成后按 Enter。

## 第 5 幕：实验结果与自动恢复（约 70 秒）

画面会显示四种方案对比、第二类批处理任务，以及小范围试运行的接受和恢复结果。

旁白：

> 先看在线服务。Agent 联合优化只付出了百分之零点九九的吞吐代价，却让最慢百分之一请求的延迟下降百分之八十二点零一，同时后台任务仍保持百分之九十八进度。相比之下，只限制后台资源虽然吞吐更高，但后台任务只剩百分之二十八，公平性明显较差。
>
> 在第二类批处理任务中，后台干扰使处理能力下降近一半。Agent 优化后，相比干扰场景恢复百分之六十点九的处理能力，较慢请求延迟下降百分之八十七点七六，后台任务仍保留百分之三十点零五，说明方案并非只对 nginx 有效。
>
> DeepSeek 候选方案让最慢百分之一请求延迟下降百分之八十四点四一，吞吐只下降百分之零点零二，因此通过安全检查。随后，更严格的测试没有达到预设门槛，系统自动恢复十九项设置并清理临时资源。这里体现了 Agent 的核心：大模型负责提出方案，真实数据和安全规则决定接受还是撤销。

[依次指向“Agent 综合效果”“第二类任务”“常规小范围试运行”和“严格安全检查”。讲完后按 Enter。]

以上数字对应本次真实运行结果。如果重新录制后数字发生变化，应按照屏幕上的实际数据朗读，不要沿用本次数字；结论也必须与屏幕上的“改善、回退、已接受或已自动恢复”保持一致。

## 第 6 幕：清理与总结（约 20 秒）

画面应显示：

```text
后台干扰仍在运行 : 否
资源控制仍有残留 : 否
自定义调度状态   : 已关闭
CLEAN: 演示环境已恢复
```

旁白：

> 最后可以看到后台干扰已经停止，临时资源组没有残留，自定义调度也已关闭。至此，系统完成了从发现问题、选择方案、真实执行、效果检查，到接受或恢复并生成报告的完整闭环。

## 常见术语的中文讲法

录制时优先说右侧中文，不需要反复念英文缩写：

| 技术名词 | 演讲时的中文说法 |
|---|---|
| procfs | 进程信息 |
| PSI | 系统压力 |
| cgroup | 资源控制组 |
| sched_ext | 可扩展调度功能 |
| scx | 自定义调度器 |
| LLM | 大语言模型 |
| workload | 工作负载或运行任务 |
| Canary | 小范围试运行 |
| SLO | 预设性能目标 |
| RPS | 每秒请求数 |
| P99 | 最慢百分之一请求的延迟 |
| rollback | 自动恢复原来的设置 |

## 录制结束后的检查

停止录屏前再展示一次版本：

```bash
git rev-parse --short HEAD
python3 -m schedx status
```

最终提交版本应与 GitLink `master` 一致。

录制完成后，将视频命名为：

```text
项目展示.mp4
```

替换仓库根目录和 `初赛作品提交材料/` 中的旧视频，再提交：

```bash
git add 项目展示.mp4 初赛作品提交材料/项目展示.mp4
git commit -m "Update final demonstration video"
git push origin master
```

视频不得超过 100 MB。
