## 当前可使用的实测证据

- 在四 vCPU openEuler SP4 虚拟机上，`59c1ca4` 与 `58903fe` 做五次成对性能对比：nginx/Redis P99 分别下降 49.48% 和 30.67%；批处理吞吐下降 2.26%，该取舍需同时披露。
- 每对旧版/新版实验均达到至少 25% 后台进度保留门槛。指标有 95% 置信区间和原始数据，不能改写为通用 Linux 性能结论。
- 原生调度版本通过 30 分钟和两小时实验；两小时有 1428 个样本和 59 次成功的超时恢复，交互类最长排队等待约 76 毫秒。
- 第二轮 `069276c` 在本地及虚拟机通过 241 项测试；其真实 HTTP 采样验证稳定状态随指标变化撤销与重建，私有进程 30 次属性设置去重及完整恢复通过。当前 `47440e2` 在两端通过 412 项测试，完整最新验收仍在进行。
- 第二轮 HTTP 实验使用采样适配器验证监测状态机，不能作为完整自主策略链或新增性能收益的证据。

上述五轮性能数据的对比对象仍是 `58903fe`，而正式初赛是 `b0591a1`。后续已执行正式初赛原生组件的同环境静态策略对比：nginx/Redis 各有五对有效样本，没有显著增益；批处理双方均未达到后台进度门槛，该组综合验收未通过。不能把历史 49.48%/30.67% 改写为“相较初赛”的提升，也不能把原生组件对测视为完整自主 Agent 对测。详见 [当前实机报告](../reports/optimization-acceptance-20261005/report.md)。

初赛测试规模已在独立临时目录通过 `pytest --collect-only` 核对为 141 项，与初赛 README 一致；这只是数量核对，不代表本轮重新执行并通过了初赛全部测试。第二轮截至 `069276c` 相对 `58903fe` 增加 74 项测试、相对初赛增加 100 项；当前 412 项相对初赛数量增加 271 项。测试数量不单独作为实质提升的论据。
