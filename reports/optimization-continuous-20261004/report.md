# 第二轮优化：持续监测与证据质量

日期：2026-10-04；基线：`e75ef3a`；分支：`codex/optimization-20261003`。

## 修复内容

旧收敛判断只检查三轮收益百分比是否接近零。已复现候选 P99 为 10、50、2 毫秒、每轮收益为 0.2% 时仍报告稳定。本轮改为同时检查实际指标波动，并要求目标、模式、专家及策略参数一致。默认采用三轮窗口、1% 容差，可通过 `--stable-window` 和 `--stable-tolerance` 配置。

缺失或无效指标、策略变化及负载变化会撤销稳定标记；稳定后继续观测。均衡模式没有吞吐指标时可以使用有效延迟指标。日志保留最多 1000 条阶段事件，会话文件记录最近 128 轮及其指标、稳定理由、已开始和已完成轮数、最终退出原因。

相同 nice、调度策略和等价 CPU-affinity 设置现在返回 `unchanged`，跳过外部命令和恢复条目追加。此前每个新候选事务都可能重复记录相同进程属性。

## 验证

- 本地及 openEuler 虚拟机：241 项测试通过，包含指标剧烈变化、策略切换、缺失/无效值、CLI 配置、故障与中断记录、150 轮历史限制和进程设置去重。
- 未定义名称与本轮修改文件的无用导入检查通过；Python 编译检查通过。
- Linux 私有进程真实设置：连续 30 次设置 nice、调度策略和 CPU 绑定，恢复日志条目数量保持不变，最后完整恢复原设置并移除日志。
- 真实环回 HTTP 采样：连续六轮测量，约 102 毫秒阶段建立稳定；约 402 毫秒负载阶段撤销稳定；后续三个稳定样本重新建立稳定。会话保留 `max_rounds` 退出原因与实际测量数据。

HTTP 实验使用采样适配器调用连续监测状态机，没有应用服务优化策略，因此不用于宣称性能提升或完整自主策略链的新实机验收。其测试容差为 10%，默认生产配置仍为 1%。本轮没有修改 BPF 调度器；上一轮五次成对性能与两小时内核实验保留为该版本的证据，没有重新引用为本轮的新性能结果。

实机脚本第一次误用默认预览模式，没有发生属性修改，失败记录已归档；显式启用真实执行后完成上述验证。

## 使用

```bash
sudo schedx run --canary-url http://127.0.0.1/ --stable-window 5 --stable-tolerance 1
```

稳定依据和轮次记录位于状态目录的 `session.json`，路径为 `metrics.continuous`。稳定不会停止持续监测。
