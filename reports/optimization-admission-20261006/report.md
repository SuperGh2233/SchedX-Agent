## 实际改进

此前 `7ee0777` 的工具入口主要在启动后应用资源策略和监测超时。本轮在保留这些合同的基础上增加：

| 行为 | 当前实现 |
| --- | --- |
| 多个独立进程同时提交 | 相同目录和配置下共享并发额度，不是各进程独立计数 |
| 交互与后台竞争 | 交互优先、等待老化、同优先级按 Agent 最近服务顺序选择，可配置交互保留位置 |
| 排队时间较长 | 排队与启动消耗原总预算；预算耗尽不启动实际命令，返回明确超时结果 |
| 调用方异常退出 | 继承租约与原资源组存活检查保留运行名额，未占用负载的失效名额可回收 |
| 同目录参数不一致或状态损坏 | 拒绝请求并保留证据，不覆盖其他调用方的状态 |
| Linux 压力变化 | 按短窗口 PSI、连续样本、冷却和额度上下限调整；缺失指标不支持扩容 |
| 判断性能改善 | 记录排队、启动、执行及提交到完成的总时延，成功完成率与后台 CPU 进度一同对照 |

使用说明与初始参数见 [工具准入说明](../../docs/tool-admission.md)。它只协调同一入口和权限域下的合作调用方，不提供原生硬配额、线程级 Agent 组公平性或新的学习路由。保留交互名额会影响批处理可用并发，需要测量其取舍。

## 失败对照与修正

初始候选五轮共 15 次工具批次均成功执行并清理，但固定/自适应总吞吐分别下降 6.4359%/7.3052%，后台批次尾部总耗时分别增加 8.2441%/9.2603%，置信区间显示稳定超过门槛。结果为 `not_accepted`，全部原始数据保留于 `first-performance-evidence.tar.gz`，SHA-256 为 `a7ff47d9fdd68517f21be116cd3abf4bd1eb32ef2d17d91f07a099db0f59f422`。

实测发现，频繁读取、锁定和重写共享状态增加了等待；测试还将状态同步放在持久日志目录，未匹配生产 CLI 的 `/run` 默认位置。`ebdc7cc` 减少不变状态的重复处理，读状态时仅有变化才写回，运行状态放到 `/run`，结束后复制到证据目录。进一步观测到单个交互保留位置会使本场景的交互突发串行，故明确测试初始额度 5、最大 8、交互保留 2，其余规则和门槛保持原值。

`068c7ba` 增加 Linux pidfd 完成通知，避免带超时的轮询等待拖延释放名额；不支持的系统保留原等待路径。等待者轮询缩短到 10 ms，同时保留状态版本缓存与周期恢复。实际硬配额短测仍生效：两秒忙循环、10% 配额使用约 0.21002 秒 CPU；原生调度、恢复、四个并发工具、启动握手、网络更新和清理短测均通过。原生程序与 eBPF 对象复用此前构建，并验证 C/头文件未变，原安装程序未覆盖。[pidfd 语义](https://man7.org/linux/man-pages/man2/pidfd_open.2.html)
