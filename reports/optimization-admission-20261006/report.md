# 第四轮：工具准入与自适应并发

本轮新增工具执行前的共享队列和有界自适应并发，代码提交为 `f265822`。本地全量 **446 项测试通过**，编译、变更文件静态检查和命令帮助检查通过。功能默认关闭，等待 Linux 实机对照后再决定默认采用；当前没有新的量化性能收益声明。

## 实际改进

此前 `7ee0777` 的工具入口主要在启动后应用资源策略和监测超时。本轮在保留这些合同的基础上增加：

| 行为 | 当前实现 |
| --- | --- |
| 多个独立进程同时提交 | 相同目录和配置下共享并发额度，不是各进程独立计数 |
| 交互与后台竞争 | 交互优先、等待老化、同优先级按 Agent 最近服务顺序选择，可配置交互保留位置 |
| 排队时间较长 | 排队与启动消耗原总预算；预算耗尽不启动实际命令，返回明确超时结果 |
| 调用方异常退出 | 继承租约与原资源组存活检查保留运行名额，未占用负载的失效名额可回收 |
| 同目录参数不一致或状态损坏 | 拒绝请求并保留证据，不覆盖其他调用方的状态 |
| Linux 压力变化 | 按短窗口 PSI、连续样本、冷却和额度上下限调整；缺失指标不支持扩容 |
| 判断性能改善 | 记录排队、启动、执行及提交到完成的总时延，成功完成率与后台 CPU 进度一同对照 |

使用说明与初始参数见 [工具准入说明](../../docs/tool-admission.md)。它只协调同一入口和权限域下的合作调用方，不提供原生硬配额、线程级 Agent 组公平性或新的学习路由。保留交互名额会影响批处理可用并发，需要测量其取舍。

## 本地验证

新增测试覆盖真实独立 Python 进程共享一个名额、调用方退出后子进程继承租约、存活后代继续占用额度、排队容量与取消、优先级/老化、状态损坏与配置冲突、状态锁超时、CPU 合同拒绝后的回收，以及排队时间消耗执行预算。

启动握手、输出边界、进程树回收使用真实子程序和文件系统替身验证；自适应规则以确定性的压力计数验证。它们没有模拟成 Linux 内核性能通过记录。

首轮全量测试为 **443 通过、3 失败**，三项原有 daemon 测试均因 macOS 临时目录导致 Unix 套接字路径过长而失败。日志和 XML 保留为 `local-tests-first.*`。随后使用独立短路径 `/tmp/schedx-admission-tests-20261006`，全量 **446 通过，失败/错误/跳过均为零**。一次摘要门禁回归还发现缺失总时延会抛 `KeyError`，已修正为保留坏样本并拒绝通过，相关测试覆盖该路径。

本轮变更文件的 F821/F822/F823/F401 检查通过；全库 F821/F822/F823 通过。扩展检查还发现七处未修改文件中的历史未用导入，本轮未展开无关清理。
